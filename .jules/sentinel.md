## 2024-05-29 - [API Key Timing Attack Vulnerability]
**Vulnerability:** The FastAPI backend used a standard string comparison (`token != _API_KEY`) to verify API keys in the authentication middleware. This exposed the application to timing attacks, where an attacker could theoretically deduce the API key by measuring the time it takes for the server to reject incorrect keys (since standard comparison short-circuits on the first mismatched character).
**Learning:** API key validation must always use a constant-time comparison function, like `secrets.compare_digest`, to ensure that the time taken to evaluate the comparison is independent of the input length and content. Both inputs must also be verified as strings using `isinstance()` prior to comparison, as `secrets.compare_digest` can raise a `TypeError` if non-string types are passed.
**Prevention:** Establish a project-wide guideline that all security-sensitive string comparisons (passwords, tokens, API keys, hashes) must use `secrets.compare_digest` or an equivalent secure comparison method, with appropriate type checking beforehand.
