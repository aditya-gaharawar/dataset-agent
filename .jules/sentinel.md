## 2024-05-24 - Timing Attack Vulnerability in API Key Comparison
**Vulnerability:** The API key verification in the FastAPI backend (`main.py`) used standard string comparison (`token != _API_KEY`). Standard string comparison operations often fail early when the first non-matching character is found, meaning the time it takes to compare two strings depends on how many initial characters match. This introduces a timing side-channel. By carefully measuring the response time of authentication requests, an attacker can theoretically guess the API key character by character.
**Learning:** Security tokens, API keys, passwords, and other secrets must always be compared in constant time to prevent timing attacks. Even though the impact might be low in certain environments or when latency is noisy, it is a fundamental cryptographic best practice.
**Prevention:** Use `secrets.compare_digest(a, b)` (in Python) or the equivalent constant-time comparison function in other languages when comparing sensitive tokens.
